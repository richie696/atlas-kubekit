## 第二批配置验收设计

| 用例 | 预期观察 |
| --- | --- |
| 模板/校验 | 生成可编辑的版本化 JSON；不连接节点，不调用系统变更 |
| 不安全配置 | 未知/重复键、凭据字段、错误类型、VIP/节点地址冲突、网段重叠均在使用前拒绝 |
| 配置存储 | 同内容导入不重写；不同内容缺少或使用旧 revision 时拒绝；文件/目录权限受限 |
| 并发导入 | 同一配置写锁下复核 revision；不同调用不得覆盖对方的新状态 |
| 配置导出 | 校验存储完整性后导出规范 JSON；不覆盖已经存在的文件 |
| 实际差异 | 正确区分一致、实际差异和无法验证；身份、IP/网卡、版本、LB/VIP 逐项有来源 |
| 只读检查 | 检查前后节点配置与服务状态保持不变；不把计划当作已应用 |
| 02 适配 | 只接受固定字段，拒绝 shell 注入；已有部署计划冲突时停止，保留原确认与身份验证 |
| 自动续跑身份 | 已核实的指纹原子写入受限 cluster.conf；重跑不重复写，生成失败不改原配置 |
| 部分不可达 | 不因少采集一台 LB 就宣布 VIP 单一持有者检查通过 |
| 多语言 | 新提示、帮助和错误使用 en/zh_CN/zh_TW 目录 |

### Cilium 受控升级用例

| 层次 | 风险与断言 |
| --- | --- |
| 制品规则 | Helm gzip 扩展头可读；版本不符、重复 Chart 元数据、损坏或过大制品拒绝 |
| 策略规则 | 不修改原私密 values；operator 零不可用、最多一个额外副本；恢复前只允许更新策略变化 |
| 中断编排 | 模板下发后 PDB 拒绝时，不驱逐 Pod、不推进其他节点、不恢复为成功状态 |
| 隔离集群 | 以整数 minAvailable 约束 DaemonSet Pod，在第一次驱逐前阻断；验证旧 agent/envoy UID 保持、锁保留 |
| 继续执行 | 显式确认原作业停止后解锁，新计划保留原 rollout owner、Chart SHA 和原策略，逐节点完成 |
| 收尾 | Helm values 与实际 DaemonSet/operator 策略一致，所有镜像匹配，五节点健康，跨节点 Service DNS 读写仍可用 |

DaemonSet 没有 scale 子资源，测试 PDB 不使用需要控制器 scale 的 maxUnavailable；
PDB 未成功观察 generation 时应拒绝驱逐，不能绕过服务端条件。

### Kubernetes 补丁与资源回收用例

| 层次 | 风险与断言 |
| --- | --- |
| 升级编排回归 | kubeadm 改回两副本/默认放置后，下一节点驱逐前恢复原 CoreDNS 布局；已完成首控制面的失败计划可生成继续计划，预览不修复资源，执行仍重新检查 PDB |
| 真实同 minor 升级 | v1.36.5→v1.36.6，3 CP 后 2 worker 串行；CoreDNS 三副本和 minAvailable=2，结束仍分布三个控制面；节点 Ready/可调度、etcd 和共享版本一致 |
| 状态保留 | 升级前后 kube-system UID 与独立 ConfigMap UID/数据一致；完成计划再执行不重装，不改变系统 Pod UID；升级后跨节点 Service DNS 仍可读写 |
| 离线前提 | 目标补丁包和镜像通过独立的签名本地仓库/缓存准备，不把这一夹具描述为工具已实现跨物料 ID 自动迁移 |
| 单批资源 | 不并行创建第二套完整集群；复用同一批部署前快照，完成后删除全部自有临时 VM/模板，保留用户原节点 |

ConfigMap 与集群 UID 的保留不证明持久卷或应用数据库恢复；后者仍需各自一致性与恢复演练。
