## Execution

Live package versions: HAProxy `2.8.16-0ubuntu0.24.04.3`, Keepalived
`1:2.2.8-1build2`, psmisc `23.7-1build1`.

The initial installation succeeded on both nodes. Both daemon validators passed,
tracking scripts were root:root 0755 and working, all three API backends were
UP on both LBs. Check-only, identical rerun, invalid port rejection and tracking
script permission repair passed on both real nodes without configuration/PID
changes. The actual phase-two password-reuse and single-owner functions also
passed using real SSH/IP/configuration reads.

Authenticated API access through `10.20.1.9:6443` succeeded. All six Kubernetes
nodes returned Ready after LB service was restored, without changes to the
control-plane or worker configuration.

### Defects found in the live run

1. **Phase-one reboot runtime was missing.** The resume service failed with exit
   127 because the initial preparation path copied the script before reboot but
   copied i18n dependencies only at enrollment, which it could never reach.
   A shared persistence function now installs runtime/catalogs before reboot
   and at enrollment. Both real nodes completed preparation and published their
   ready manifests after resuming with the corrected source.
2. **SSH validation could fail on a correct configuration.** `sshd -T | grep -q`
   under pipefail could terminate the producer with SIGPIPE. The check now
   captures the complete output before matching. Large-output regression and
   the real resume path both passed.
3. **A standby could not bind a business VIP-specific listener.** HAProxy logged
   `Cannot assign requested address` for `10.20.1.20:16443` during standby reload.
   An active-VIP request alone initially missed this condition, so the route
   acceptance case now checks the listener on *both* nodes and exercises route
   failover. LB setup now persists/applies `net.ipv4.ip_nonlocal_bind=1`; the
   configuration file and previous kernel value participate in rollback.

Timings are observations from this run, not availability guarantees. In
particular, stopping HAProxy caused failed requests during takeover. The active
reboot harness initially treated the intentionally offline SSH target as a
failure; it was corrected to permit that target to be unreachable while still
requiring the survivor to serve the API, and the case was rerun successfully.

The last idempotency oracle initially compared raw JSON bytes and exact file
modes inherited from the manager. The manager writes compact JSON and mode
0600, while the installer normalizes JSON formatting and sets HAProxy config
0644 / Keepalived config 0640. These differences did not restart daemons.
The corrected check compares parsed state, daemon config bytes, unchanged PIDs
and VIP assignments, and final policy modes. Both nodes passed. A regression
case now covers compact manager JSON followed by an installer rerun.
