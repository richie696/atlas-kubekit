# 持续运维功能定义

读者：实施、运维及维护者。适用正式版本：0.3.0。
状态：本轮定义的开发范围与隔离验收完成，发布依据见 [发布验收](validation/release-0.3.0.md)。本文件主管功能范围与验收要求，
实现设计见 [运维核心设计](architecture/operations-core.md)。

## 定位和现有基础

通过简单的脚本选项完成复杂集群的部署与维护，使环境可重复部署、变更可预览、
故障可诊断、备份可恢复。现有 01～05 继续承担准备、部署、插件、巡检和 LB 管理；
新增能力应复用其稳定规则，不把生产部署测试等同于所有后续运维操作都已验证。

## 第一批用户结果

第一批形成“观察 → 计划 → 显式执行 → 记录结果”的纵向切片，覆盖 OPS-01/02/03 的首批用例。
`06-maintain-cluster.sh` 已接入安全检查、统一报告、备份创建/校验和恢复计划。
使用方式见 [运维指南](operations-guide.md)。后续批次已接线隔离恢复、收尾变更、诊断包和生命周期，
最新执行边界见上表及 [真实执行记录](validation/operations-e2e-20261110-execution.md)，不能从早期只读计划推导为已经完成。

### OPS-01：安全收尾

- 默认只读采集；展示事实、建议与不能验证的项目。
- 分别识别脚本创建的 bootstrap sudo 文件、活动配对服务及 LB stats 监听范围。
- 删除部署授权前验证保留的管理通道；缺少替代运维授权时禁止删除，避免破坏 02/05。
- 只处理本工具拥有的文件和服务；不编辑用户自建 sudo 规则或覆盖整个 authorized_keys。
- 真实收尾需要显式确认及重新采集；失败保留证据和可恢复配置。

### OPS-02：备份与恢复

- 明确保护对象：etcd 集群状态、配置/PKI、卷、应用数据库分别登记覆盖状态。
- 备份清单包含格式版本、工具版本、执行编号、源集群/节点身份、创建时间、对象类型、
  文件相对路径、大小及 SHA-256；不包含明文凭据。
- 备份目录和私密材料采用 root-only 权限；加密/外部存储需要独立密钥或凭据引用。
- 采集失败不生成“成功”清单；校验失败、身份不符或不完整时拒绝恢复。
- 恢复计划清楚说明停机、现有数据处置、依赖版本、操作顺序与恢复后检查。
- 第一批先交付备份/校验和恢复计划；生产 etcd 恢复及卷/数据库恢复适配在完成各自详细设计、
  隔离演练和明确的目标环境确认后接线，不把计划生成功能称为恢复成功。
- 对备份年龄、保留周期和恢复时间不编造默认生产 SLA；由环境配置决定。

### OPS-03：统一报告

- 为一次采集/执行生成唯一 runId，结果包含工具版本、目标、时间、阶段及结果。
- 单项结果采用 PASS/FAIL/WARN/SKIP/UNVERIFIED；无法运行命令不得解释为通过。
- 常规报告只保存允许的字段；不得默认收集私钥、kubeconfig、etcd 数据或 Secret。
- 输出 JSON 和文本视图；诊断包以明确的采集白名单构建，文件大小和执行耗时有上限。
- 公开分享前仍提示使用者审核内部 IP/用户名等环境信息；不能以自动过滤宣称绝对无敏感信息。

## 第二批用户结果

06 提供配置模板、校验、导入、导出和实际环境差异检查；身份、网络、版本及 LB/VIP 分项核对，
不能验证的字段独立呈现。02 可消费相同配置，保留部署确认、存储与节点身份检查，拒绝覆盖冲突计划。
完整协议和命令见 [统一集群配置](cluster-configuration.md)，实际验证见
[第二批验证](validation/operations-e2e-20261110.md)。第二批没有实现任意配置自动应用、
跨管理机变更锁，也没有在当前生产集群重新执行初始化。

## 跨功能要求

- 计划对象不可变，计算规则不执行远端命令；执行层按已验证动作白名单工作。
- 使用集群/操作范围锁防止重复变更；日志与状态写入使用原子替换和受限权限。
- 计划必须与目标身份和采集指纹绑定；执行前重新检查，拒绝过期或被修改的计划。
- 操作不会自动升级或重启未列入计划的服务；取消、局部失败和清理有明确结果。
- 新功能保持英文、简体和繁体目录及回退契约；底层工具输出与用户摘要分开。
