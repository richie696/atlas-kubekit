# 监控故障定位指南

## 按故障现象快速定位

| 生产现象 | 排查编号 | 常见可能原因 |
|---|---|---|
| 告警完全没有触发 | MON-01、MON-02、MON-03、ALERT-01 | Exporter 未运行、Target 未发现/不新鲜、Prometheus 未加载规则、表达式标签与实际指标不匹配 |
| 告警触发但没有通知 | ALERT-01、ALERT-02、ALERT-04、ALERT-05 | Alertmanager 路由未匹配、静默/抑制规则遮蔽、接收器配置错误、SMTP/机器人网络或认证失败 |
| 邮件收到了但没有具体内容或样式异常 | ALERT-03、ALERT-05 | 模板正文缺少规则注解、HTML 未被加载、邮件客户端显示方式异常；也要检查 Operator 实际采用的路由/模板 |
| 通知缺少相关错误日志或日志链接打不开 | MON-05、ALERT-06 | 检查采集范围/日志新鲜度、告警对象到查询模板的映射、Loki 权限/查询状态、消息长度上限；若带链接，检查 Grafana HTTPS 证书、认证、当前网络到入口的连通性（内网域名需内网或 VPN） |
| 节点显示 Ready，但服务无法工作 | NODE-01、NODE-02、CP-01、NET-01 | kubelet/containerd 异常、控制面依赖故障、DNS 解析失败、应用自身探针或外部依赖异常 |
| Pod/PVC 显示正常，但应用不可用 | WORK-01、STOR-01、NET-02 | 副本/发布卡滞、容量或挂载问题、策略阻断、业务端点不健康 |
| 节点网络变慢、丢包或连接排队 | NET-03 | 先核对告警网卡及收发方向，再查容量配置、出口整形、TCP 重传和监听队列。遥测告警先检查采集源或容量数据。 |
| 控制面 VIP 不通或主 LB 故障后中断 | LB-01、LB-02、LB-03、LB-04 | HAProxy 失效、Keepalived 未接管、VIP 无主/双主、监控 ACL 或后端路由异常 |
| VIP 能建立连接，API 却无法完成写入 | CP-02、CP-04 | 先核对各 API Server 后端和 `/readyz` 的 etcd 项，再检查成员和仲裁；TCP 握手成功时 etcd 仍可能不可写。 |
| Longhorn 卷降级、重建失败或数据异常 | STOR-02、STOR-03、STOR-04 | 副本所在节点/磁盘不可用、容量不足、Manager 指标采集缺失、Longhorn 通信策略异常或副本恢复后数据不一致 |
| 监控栈整体失联，集群内告警也收不到 | OBS-01、OBS-02 | Prometheus/Alertmanager 同时不可用、监控与业务共享故障域、独立观察器或外部通知链路失效 |

## 登录与日志详情

| 症状 | 检查位置 |
| --- | --- |
| 点击告警链接后又出现 Grafana 本地登录框 | 核对入口域名、网关的 OIDC 回调、身份转发与 Grafana SSO。用新浏览器会话打开原邮件链接，确认回到 Explore 的原查询和时间窗口。 |
| 授权回调出现 OAuth flow failed | 对照 Envoy 回调和 AS 令牌端点同一时间段的日志。若报告 `issuer-signing-key-unavailable`，由 AS 管理员核对活动签名密钥能否解密及公钥轮换状态。 |
| Grafana 可进入但找不到错误行 | 核对 Viewer 的 Explore 权限、Loki 数据源 UID、告警对象标签、日志保留期和邮件链接中的时间范围。 |

## 故障排查顺序

当生产出现告警或监控盲区时，按以下顺序缩小范围：

1. **先确认对象和时间**：记录集群、namespace、node/Pod/LB/PVC、告警名、severity、开始时间和观测值。
2. **确认指标是否可信**：看对应 Target 是否存在、是否 `UP`、最近样本时间是否小于配置的 `monitoring-max-age`。Target 缺失或样本过期时，先处理采集链路，不要把“没有数据”当成“对象健康”。
3. **确认规则是否被加载**：查看 Prometheus Rules 中的规则状态、PromQL 结果和告警状态。若指标为 `UP` 但规则不触发，检查 label、job/instance、指标名、窗口、阈值和 `for` 时长。
4. **确认通知是否发送**：在 Alertmanager 查看路由匹配、receiver、silence/inhibition、发送成功/失败指标；对照 ALERT-01～05 检查具体渠道。
5. **核查故障域和业务路径**：节点健康不等同 API VIP/业务入口健康；Pod Ready 不等同端到端业务请求成功；Longhorn 卷健康不等同备份可恢复。
6. **只在隔离环境重放故障注入**：使用对应 E2E 脚本做主动停止服务、网络策略阻断、VIP 添加/移除或存储副本操作。生产环境不要照搬破坏性步骤；先使用只读诊断、明确影响范围并按正式变更流程操作。
7. **恢复后核验全链路**：不只看故障告警消失；同时核验 Target、新鲜指标、规则 inactive、渠道恢复通知、节点/Pod/PVC/Longhorn/VIP 实际状态及业务探测。

## 按编号排查生产风险

| 编号与检查项 | 可能原因或应核对的风险 |
| --- | --- |
| MON-01 监控插件首次安装 | 首装遗漏组件、资源未 Ready、版本或 values 不兼容、规则未加载、重建后历史数据丢失。 |
| MON-05 首装监控诊断流程 | 检查中心组件是否 Ready、PVC 是否 Bound、采集端能否写入，以及通知路由是否被选择。 |
| MON-06 Loki/Alloy 首装配置 | 日志没有采集、Pod 重建造成日志库丢失、重复日志污染排查、采集器权限过宽或错误 Loki 地址导致日志无数据。 |
| MON-02 Prometheus 目标发现 | 页面有规则但没有数据、目标 `DOWN`、目标重复、资源标签不匹配或采集过期。 |
| MON-03 规则加载与表达式 | Prometheus 启动失败、表达式从不触发、误报、指标缺失未告警或恢复后告警不清。 |
| MON-04 告警中文内容 | 告警只有代码名/英文标签、缺少对象或无法判断处理动作。 |
| MON-07 逐风险采集覆盖审计 | 组件未被采集、抓取目标漂移、目标 UP 但数据过期，以及多个抓取池共享 `job/instance` 时样本归属错误。排查时先看目标清单，再查看样本状态和 `attribution`。 |
| MON-08 日志链路自监控 | 日志诊断持续缺失、Loki 拒收、Alloy 投递丢弃或采集断开。 |
| MON-09 监控页面公网/内网入口与 OIDC | 页面 URL 无法访问、错误证书、OIDC 回调不匹配、私有 CA 未注入网关导致授权/令牌交换失败、Prometheus/Alertmanager 意外绕过认证，HAProxy 只在一侧生效，或通知里带了无法访问的链接。排查 DNS 指向应用 VIP、VRRP/VIP 登记、双节点 HAProxy 配置一致性、NodePort/节点防火墙、证书 SAN/有效期和私钥匹配、Gateway/Route/BackendTLSPolicy Conditions、IdP 回调和 OIDC Secret 引用。 |
| NODE-01 节点资源和数据新鲜度 | 节点负载过高、磁盘/inode 耗尽、Exporter 停止、采集延迟；用于识别是真实资源压力还是监控数据失真。 |
| NODE-02 kubelet/containerd 服务状态 | 节点仍在线但 kubelet/containerd 停止或卡死；区分“机器网络可达”与“Kubernetes 运行时健康”。 |
| CP-01 API Server 目标 | 控制面进程挂掉、目标遗漏或 Prometheus 访问不到控制面指标。 |
| CP-02 etcd 成员与多数派 | etcd 失去 quorum、成员无法通信、控制面写请求超时或成员指标不全；用于区分“单成员失联但仍可服务”和“多数派丢失”。 |
| CP-03 Alertmanager 端点健康 | Prometheus 仍采集正常但告警无法送出；区分“没有告警”与“通知执行器失效”。 |
| CP-04 三控制面 API 入口与恢复 | 控制面少数节点退化、LB 入口检查与 etcd 实际写入状态不一致、失去多数派后数据未恢复或采集告警未解除。 |
| NET-01 CoreDNS | 服务名解析失败、DNS 错误率升高、解析变慢、CoreDNS 副本不足或采集缺失。 |
| NET-02 黑盒网络探测 | 出口策略/路由阻断、HTTP 路径错误、Service 不可达、抓取失败或旧失败样本维持告警。先对照 `up` 与 `probe_success`，再用 `probe_target`、`source_node` 和 `probe_http_status_code` 定位。 |
| NET-03 节点网卡与 TCP 质量 | 网卡饱和、内核丢包、TCP 路径劣化、应用接受连接过慢，以及网卡报告速率缺失或采集重复导致的误判。 |
| WORK-01 Deployment/StatefulSet/DaemonSet 健康 | 滚动发布后副本不齐、StatefulSet 实例不可用、DaemonSet 节点覆盖不足。 |
| WORK-02 Pod 启动与容器故障 | CrashLoopBackOff、镜像拉取失败、容器频繁退出或因资源问题被杀。 |
| WORK-03 发布卡滞 | 新版本无法推进、发布超时、卡在新旧 ReplicaSet 切换。 |
| WORK-04 CronJob/Job 与弹性伸缩 | 定时任务没有完成、伸缩停止、外部指标源/DNS 故障、KEDA Operator 失联。 |
| LB-01 HAProxy 指标目标和后端 | LB 进程停止、Prometheus 抓取断开、后端全部不可用或健康状态不明。 |
| LB-02 HAProxy 队列、连接错误和前端容量 | 业务请求积压、连接失败升高、前端连接接近上限；用于排查容量或后端响应能力。 |
| LB-03 Keepalived 正常切换 | 主 LB 故障后控制面入口中断、备用 LB 未接管或恢复后 VIP 未回到预期节点。 |
| LB-04 VIP 无主/双主/漂移 | VIP 不存在、同时绑定两台 LB、网络分区或 Keepalived 频繁切换。 |
| LB-05 ACL 与 VIP 指标入口 | Target 404/403、端口被意外公开、Prometheus 来源不在 ACL 内、安装只发了 CR 而未部署主机采集器。 |
| STOR-01 PVC 空间 | 文件系统卷写满、容量指标消失、Pod 重挂载后数据异常。 |
| STOR-02 Longhorn 指标采集和 NetworkPolicy | 磁盘/副本告警无数据、指标端口策略过宽或合法采集被误拦。 |
| STOR-03 Longhorn 磁盘和副本状态 | 磁盘空间耗尽、磁盘未 Ready、不同 Manager 重复抓取造成错误值。 |
| STOR-05 CSI VolumeAttachment 状态 | 卷附加未完成或 CSI 状态采集断流；用于区分真实未附加与 kube-state-metrics 数据缺失。 |
| STOR-04 Longhorn 故障恢复和数据校验 | 节点/副本故障后数据是否仍可读、重建后内容是否保持一致。 |
| ALERT-01 Alertmanager 规则投递 | 规则已 firing 但没有通知，或 resolved 消息缺失/告警身份不一致。 |
| ALERT-02 分组、合并和恢复 | 告警重复刷屏、不同集群/团队被混组、静默到期后没有重新通知、更新/恢复通知不符合预期。 |
| ALERT-03 邮件 SMTP/TLS/中文 HTML | SMTP 连接/认证失败、正文为空/纯文本、触发信与恢复信内容不一致。 |
| ALERT-04 企微/钉钉/飞书 Webhook | Alertmanager 显示发送失败、机器人关键字校验拒收、Webhook 配错或恢复通知遗漏。 |
| ALERT-05 受管渠道配置和 Secret 引用 | 安装或运维配置误覆盖现有路由、Secret 不存在/键名错、凭据泄漏。 |
| ALERT-07 菜单 18/19 首次通知渠道配置 | 首装遗漏通知路由、Webhook 凭据发往错误主机、Secret 泄漏、中继镜像不可拉取、确认误操作或恢复通知遗漏。 |
| ALERT-06 告警关联日志与可选链接 | 值班人收到症状却找不到故障证据；通知含过多或敏感日志；无公网入口时链接不可用；无效链接暴露内部地址；Loki 不可用时告警被吞掉。 |
| OBS-01 独立观察 API/DNS/通知队列 | 集群内监控整体失联、外部入口故障，或观察器进程卡死/退出造成监控盲区。 |
| OBS-02 监控系统自监控 | 监控栈自身停止后仍误以为集群健康；集群内 Prometheus 已停机时其规则不能继续通知。 |
| HUB-01 中心首次部署 | 中心没有接收端、中心栈装在业务集群内、中心故障后监控历史或告警配置丢失。 |
| HUB-02 业务集群 Agent 部署 | 业务集群内仍重复部署全套监控、Agent 缺少必要采集或身份标签、凭据进入计划/日志。 |
| HUB-03 多集群身份隔离 | 集群数据混淆，排障查询或告警错误归属到另一集群。 |
| HUB-04 Remote Write 中断与恢复 | 网络抖动造成数据丢失且没有告警，或恢复后无法补传。 |
| HUB-05 日志推送中断与恢复 | 错误日志仅保留在业务集群，日志转发静默失败，或重复转发/丢日志。 |
| HUB-06 中心规则归属 | Agent 模式不执行规则，规则看似部署成功但告警永不触发，或跨集群聚合错。 |
| HUB-07 中心不可用与外部观察 | 中心整体故障导致本地和中心告警一起不可用，无人发现监控平台自身失联。 |
| HUB-08 安全与网络边界 | 为采集开放不必要的入站端口、跳过 TLS 验证、密钥泄露或轮换导致长期断采。 |
| HUB-09 迁移与幂等 | 改模式时误删历史数据/凭据，或重复安装造成双重规则与重复告警。 |
| HUB-10 离线和版本兼容 | 离线生产无法安装、Operator/Chart 版本不支持 Agent、升级后 Agent 无法加载。 |
