读者：集群管理员、业务负责人及维护者。修订：2026-11-15。
状态：0.4.0 候选发布风险目录；工作树改动尚未发布。现有正式发布版本为 0.3.0 / `269d186`。客户业务和未登记范围须由集群负责人按环境完成 QA，缺少配置不得判为健康。

## 读法、来源与状态

每行是需要覆盖的风险，不强制等于一个指标或一条告警。信号列为语义目录，
不是可直接执行的指标名/PromQL；落地前必须补齐实际版本、类型、单位、标签、阈值、
窗口、缺失处理与恢复条件。禁止将多个相关信号简单相加后当作风险。

适用：**通用**为所有目标集群的候选基线；**在用**为登记使用该组件/设施时必需；
**扩展**由业务与外围依赖清单决定。尚未部署的规划组件不产生目标缺失告警；
已登记的组件采集不到是覆盖缺口，不是“不适用”。不适用需原因、依据、责任人及复核时间。

### 0.4.0 风险范围处置

- 节点、控制面、网络/DNS、工作负载、监控自身，以及已登记的 LB、Cilium、Longhorn/CSI 和证书，是本版本的条件/通用监控基线。真实采集或目标登记缺失必须留在“未覆盖/未验证”。
- 业务 API 的可用性探测可以使用已配置的 HTTP(S)/DNS 探针；成功率、P95/P99、登录/交易等业务语义必须由业务方给出目标、SLO 和安全测试方式。没有这些输入时不能标记业务风险已覆盖。
- Gateway/Ingress 若在目标环境实际承载生产流量，属于必需风险；本版本没有通用控制器指标适配器，覆盖报告应保留缺口。Gateway/Ingress 的管理和控制器适配列入 0.7.0，不能据此把其他目标环境自动标为不适用。
- 数据库、缓存、消息队列、对象存储等扩展信号依赖具体产品、Exporter 和业务阈值；未登记具体服务时显示为待评估，已登记但无采集/规则时显示未覆盖。
- 备份年龄、备份校验、异地副本与恢复演练状态的周期监控归入 0.5.0。若目标环境正在使用备份保护，0.4.0 报告须明确显示此缺口；本版本的一次性备份/恢复操作不算持续监控。

## 缺口如何成为交付目标

风险条目采用稳定 ID；后续增加实际规则时记录其映射，允许一项风险对应多条规则。
每个部署配置分别记录适用性、采集状态、规则状态、通知状态和验收状态，不压成单个“已安装”。
建议展示：未覆盖、已配置待核验、有范围的已验证、不适用；原因、版本和证据必须随状态保存。
缺失数据属于未覆盖/未核验，不能转换为健康或自动恢复。

通用/在用基线与业务扩展须分别列出覆盖分母。不能把未实现的在用组件排除后宣称覆盖完整。
精确阈值、SLO、渠道对象、资源预算和首批实现范围须在评审和环境配置阶段确定；
本文只确立覆盖目标，不授权发送通知、注入故障或启动测试资源。
