# 0.4.0 监控方案安装指南

在独立监控集群安装中心，再将各业务集群的采集端接入中心。两种操作都运行 **03 号脚本，菜单 19「按集群用途配置监控」**。[组件与部署位置](05-监控中心与业务集群架构图.md)

## 安装前准备

| 项目 | 需要准备的内容 |
| --- | --- |
| 集群 | 02 阶段已登记集群用途，中心为 `monitoring`，业务为 `application`。在持有目标集群管理员 kubeconfig、能运行 kubectl 和 Helm 的控制平面节点执行。生产使用独立 HA Kubernetes；资源紧张且无需 HA 的开发或测试环境可评估已有 K3s，02 不安装 K3s。 |
| 存储 | 选定可动态供给持久卷的 StorageClass，按指标和日志保留期准备容量。明确组件副本、故障域与备份策略。 |
| 页面入口 | 若启用 HTTPS，准备基础域名，给 ops、grafana、prometheus、alertmanager 四个主机名配置 DNS 解析，准备覆盖这些主机名的 TLS Secret 或证书与匹配的私钥。内网模式准备入口 VIP、双 LB 的 SSH 访问和客户端信任的 CA；公网模式准备外部 DNS、负载均衡或 NAT。 |
| 统一登录 | 在独立 AS 注册 OIDC 客户端，准备 Issuer、Client ID、Client Secret，根据向导列出的地址登记回调。使用私有 CA 的 AS 需提供相应 CA。给要登录的个人账号授权访问该客户端。 |
| 通知 | 按需准备 SMTP 主机、端口、TLS 模式、发件人、收件人和凭据，或企微、钉钉、飞书机器人的 Webhook 与平台要求的关键词、签名配置。 |

## 先安装监控中心

1. 在监控集群的控制平面节点，从工具目录运行下列命令，选择下载源后输入 `19`。

   ```bash
   sudo bash ./03-install-addons.sh --lang zh_CN
   ```

2. 核对当前集群和角色，确认部署独立监控中心。按各阶段提示选择 Prometheus 栈和 Loki/Alloy 的存储、容量、保留期及日志采集范围。脚本安装组件并等待工作负载就绪。
3. 选择页面访问方式。启用 HTTPS 时，按提示配置域名、TLS 和 OIDC。内网双 LB 方案还会核对 VIP 与转发目标。按向导在浏览器完成登录校验，保存安装报告里的门户及组件地址。
4. 选择所需通知渠道，填写收件人和凭据，核对预览，再按提示用完整计划 ID 确认。已验证的 Grafana HTTPS 入口及 Loki 数据源可用于生成日志详情链接。内网链接需要内网或 VPN；缺少有效入口时，诊断通知提供限长、脱敏的日志片段或查询状态。

## 接入业务集群

在每个 `application` 集群重复执行同一命令并选择 `19`。先准备从该集群可访问的中心 Remote Write、Loki HTTPS 写入端点，在向导所用的命名空间准备各自的认证 Secret 和所需 CA。写入端点与浏览器页面地址用途不同。

按提示输入唯一集群 ID、两个写入地址、Secret 名称和键、CA 引用及日志命名空间。部署后，在中心 Prometheus 按 `cluster` 标签查看新鲜样本，并在 Grafana 的 Loki 数据源查找该业务集群最近一条已知日志。对同名 Pod 或服务也应能区分来源集群。

## 失败续作与交付检查

处理报错后回到相同集群，重跑 `03 → 19`。向导逐阶段检查已有组件和受管资源，必要时重新确认配置。旧集群已有监控栈且归属不清时，先核对数据卷和迁移安排。

- 从安装报告打开运维门户，用获准的个人账号登录，再进入各组件。报告默认保存在执行用户的 `~/.local/state/atlas-kubekit/reports/`。[页面与入口清单](06-运维门户页面与组件入口清单.md)
- 在 Prometheus 查看 Targets 与 Rules，在 Grafana 确认近期日志，在 Alertmanager 检查通知路由。用约定的测试告警检查触发及恢复收件。
- 从实际收件箱打开日志链接，确认授权后回到原查询与时间窗口。若只读用户也能执行写操作，核对应用和入口的权限策略。
- 某一步失败时按症状查阅[监控故障定位指南](04-监控故障定位指南.md)。增加采集目标、调整规则和路由可查阅[监控运维配置指南](03-监控运维配置指南.md)。
