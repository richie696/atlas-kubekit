# 持续运维功能定义

阅读位置：`04.01` · 功能域：持续运维 · [返回文档导航](../00-文档导航.md)。

读者：集群管理员。适用版本：0.3.0 及后续兼容版本。
本文说明持续运维入口提供的能力、适用场景和保护边界。

## 定位和现有基础

通过简单的脚本选项完成复杂集群的部署与维护，减少手工重复操作，让管理员先了解影响、
再确认变更，并保留发生中断后的处理依据。现有 01～05 负责主机准备、集群部署、插件、
巡检和 LB；06 提供集群配置及后续运维功能。

## 功能与用户痛点映射

| 能力 | 解决的问题 | 提供的功能 | 边界 |
| --- | --- | --- | --- |
| 安全交接 | 部署阶段临时授权不应长期保留 | 识别工具创建的授权和配对服务，核对替代管理通道后生成收尾计划 | 仅管理工具自己创建的授权；不修改用户自建账户策略 |
| 配置与变更 | 多台主机上的状态容易产生差异 | 配置模板、导入导出、环境差异检查、变更预览和显式执行 | 只执行脚本支持的操作，不自动应用任意配置差异 |
| 节点与组件维护 | 节点加入、退出或升级涉及顺序和工作负载保护 | worker 生命周期管理、Kubernetes/Cilium 补丁升级和继续处理 | 不自动变更控制面成员；升级失败时停止并提供后续处理入口 |
| 备份与恢复准备 | 备份文件不等于可恢复数据 | 控制面加密备份、完整性检查、恢复计划、隔离恢复；登记卷和应用数据保护信息 | 不执行任意数据库或生产原位恢复；应用数据和卷需单独设计备份与恢复 |
| 报告与诊断 | 排障信息散落在命令和节点日志中 | 统一 JSON/文本摘要和白名单诊断包 | 默认不收集私钥、kubeconfig、Secret 或原始特权输出；分享前检查环境标识 |
| 离线交付 | 公共源或互联网在生产网不可用 | 锁定依赖、镜像、Chart 和工具物料，支持签名 APT 及受限网络部署 | 当前基座面向 Ubuntu 24.04 amd64；私有认证凭据及跨物料 ID 在线迁移需另行处理 |
| 多语言 | 团队成员使用不同语言操作 | 英文、简体中文、繁体中文目录和共享 messageKey 回退机制 | 第三方工具输出仍由其自身语言设置决定 |

## 安全收尾

- 默认只读采集；展示事实、建议与不能验证的项目。
- 分别识别脚本创建的 bootstrap sudo 文件、活动配对服务及 LB stats 监听范围。
- 删除部署授权前验证保留的管理通道；缺少替代运维授权时禁止删除，避免破坏 02/05。
- 只处理本工具拥有的文件和服务；不编辑用户自建 sudo 规则或覆盖整个 authorized_keys。
- 真实收尾需要显式确认及重新采集；失败保留证据和可恢复配置。

## 备份与恢复准备

- 明确保护对象：etcd 集群状态、配置/PKI、卷、应用数据库分别登记覆盖状态。
- 备份清单包含格式版本、工具版本、执行编号、源集群/节点身份、创建时间、对象类型、
  文件相对路径、大小及 SHA-256；不包含明文凭据。
- 备份目录和私密材料采用 root-only 权限；加密/外部存储需要独立密钥或凭据引用。
- 采集失败不生成“成功”清单；校验失败、身份不符或不完整时拒绝恢复。
- 恢复计划清楚说明停机、现有数据处置、依赖版本、操作顺序与恢复后检查。
- 备份校验和恢复计划不会替代卷/数据库恢复，也不代表应用恢复已经完成。
- 对备份年龄、保留周期和恢复时间不编造默认生产 SLA；由环境配置决定。

## 统一报告与诊断

- 为一次采集/执行生成唯一 runId，结果包含工具版本、目标、时间、阶段及结果。
- 单项结果采用 PASS/FAIL/WARN/SKIP/UNVERIFIED；无法运行命令不得解释为通过。
- 常规报告只保存允许的字段；不得默认收集私钥、kubeconfig、etcd 数据或 Secret。
- 输出 JSON 和文本视图；诊断包以明确的采集白名单构建，文件大小和执行耗时有上限。
- 公开分享前仍提示使用者审核内部 IP/用户名等环境信息；不能以自动过滤宣称绝对无敏感信息。

## 操作方式

菜单和命令行共用同一执行流程：读取目标环境，生成带影响说明的计划，由管理员确认后执行。
中断时保留状态供检查和继续处理。完整命令、交互选项和恢复方式见[持续运维操作指南](04-持续运维操作指南.md)。
